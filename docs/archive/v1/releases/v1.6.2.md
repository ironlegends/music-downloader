# Music Converter v1.6.2

Post-audit fixes for v1.6.1. No new features.

## Fixes

### 1. Extension downloads — setVolatileUrl instead of registerDownload

onSuccess in src/browser/entries/extension.js and the extension/content-script.js bundle called panel?.registerDownload?.(), which does not exist in mountPlaylistPanel. The actual method is setVolatileUrl. As a result, the download button was never displayed after a successful conversion.

### 2. MV3 service worker — no body on GET/HEAD

extension/service-worker.js passed body: signed.body even for GET requests (for example, /api/bridge/status), causing TypeError: Request with GET/HEAD method cannot have body in the service worker. The fix sets body only for methods that accept it.

### 3. USB — exclusive publication and mount-letter changes

Publication moves the completed .part file through a PowerShell wrapper invoked by execFile with separate arguments and shell:false. It calls System.IO.File.Move(source, destination), the two-argument overload compatible with PowerShell 5.1. This atomic no-replace primitive works on FAT32, exFAT, and NTFS and guarantees that existing files are never overwritten. Node's API does not provide a portable no-replace rename primitive. The publisher never creates a partial final file: on failure or removal, only the .part file remains. On an EEXIST collision, the other file is preserved and the next suffix is selected. The check does not depend on stats.dev or stats.ino. If the mount actually changes drive letters, only the regular, non-symlinked, contained .part file revalidated against the same volume identity can be moved; the old path is ignored.

### 4. Bridge — fail-closed configuration and launcher lifecycle

The bridge starts only if bridgeAllowedOrigins or MUSIC_CONVERTER_EXTENSION_ORIGINS contains valid exact origins. Otherwise, the main server remains available in the explicit disabled-unconfigured or disabled-invalid state, without a listener or secret. With valid configuration, the launcher starts the bridge on 127.0.0.1:3210 with the same allowlist for CORS and authentication, then invalidates the session and closes the queue at shutdown.

### 5. release.yml workflow — explicit failure when notes are missing

The silent fallback to docs/releases/v1.6.0.md concealed the absence of the expected notes file. It was replaced with exit 1 and an explicit message.

### 6. check-artifacts.mjs — usage message when no argument is supplied

Without a positional argument, the script produced an ERR_INVALID_ARG_TYPE stack trace. It now prints a readable usage message and returns code 1.

## Evidence and QA status

### Automated — PASS

- The actual extension bundle mounts the v1.3 runner and panel, remains passive on mount, and renders the download button only after an HTTPS success.
- Trusted bridge controls cover Connect, local approval, Confirm, and voluntary sending of core results.
- The service worker keeps the nonce and key, fixes routes and methods, omits the body for GET/HEAD, and signs HMAC POST requests.
- The USB commit uses an exclusive primitive, never replaces a concurrent file, and finds the .part file after a simulated real mount move.
- The CLI prints Usage without a stack trace when no argument is supplied; the exact release notes file is required.

### Chrome, Edge, Windows, pairing, and physical USB — PENDING

No physical evidence is fabricated in this fix. Real Chrome/Edge installation, local pairing, drive-letter changes, device removal, read-only behavior, and full-volume tests remain separate manual gates before publication.
